# UI-2026-10-26 · 月历改「连续滚动」（周为单位）

用户原话：

> 「我发现一个下滑翻页时一整月的这样体感不好举个例子进度条直接从1到100天直接了，要慢慢来参考我的截图，
> 一行一行的来也可以大力下滑直接一直往下滚，但是不要出现下滑就是滚动一个月。简述：向下滑，日历就像
> 一张长长的纸，一天一天、一周一周（一行一行）地连续往下滚动。滚动到月底后，无缝衔接下一月。」

改造前：`CalendarCard` = 固定 42 格 + `detectVerticalDragGestures` 整月替换。
改造后：`LazyColumn`，**一项 = 一周**，预生成当月前后各 24 个月。

## 代码落点

| 文件 | 变化 |
|---|---|
| `calendar/WeekScroll.kt`（新增） | 纯逻辑：`weekStart` / `weeks` / `rangeFor` / `headerMonth` / `indexOfWeekContaining` / `indexOfFirstWeekOfMonth` / `shiftMonth` / `monthTitle` |
| `data/WeekRow.kt`（新增） | `WeekRow(date, cells)` + `WeekRows.build`（给每格填内容，灰化靠「这一行的主月」） |
| `data/TookRepository.kt` | 新增 `loadWeeks(fromDate, toDate)`，复用 `MonthExpander.itemsOn/memosOn` 与 `doneKeys()`，整段**一次**读库 |
| `ui/CalendarScreen.kt` | `CalendarCard` 换成 LazyColumn；顶部标题改 `derivedStateOf` 跟随 `firstVisibleItemIndex`；‹ › 改 `animateScrollToItem` |
| `ui/Theme.kt` | 新增 `calendarViewportHeight = 420.dp`；删除 `calendarFlipThreshold` |
| `calendar/MonthGridLayout.kt` | `monthFlip` 标注废弃（保留 + 3 条既有测试不动，见下） |

**`DayCell.inMonth` 的语义变了**：连续滚动里没有「补位的上月/下月」，它现在表示
「这一格属于本行 7 天里天数最多的那个月（主月）」。跨月行里少数那侧灰掉，同一行的颜色恒定 ——
滚动途中不会整屏闪烁。桌面月历组件（`MonthWidgetPlan`）走的是 `loadGrid`，语义没变。

## 废弃说明

`MonthGridLayout.monthFlip` 与 `TookDims.calendarFlipThreshold`：UI 已不再调用。
`calendarFlipThreshold` **已删除**（无引用）；`monthFlip` **保留**，因为
`MonthGridLayoutTest` 有 3 条 `monthFlip_*` 回归测试仍在跑它，删除需连测试一起删。
本次按「留着不删、UI 不再调用」处理，理由写在方法注释里。

## 真机证据（小米 13 / 5bf0cda4 / Android 15）

滑动都在日历滚动区内（y≈1250→950），`uiautomator dump` 的
`content-desc="calendar-weeks 起始周 <周一>"` 直接给出视口最上面那一周。

### 1. 轻滑一次 = 滚 1 行

```
① 起始     | 标题=2026 年 10 月 | 视口首行=2026-10-26 | 可见 2026-10-26 … 2026-12-06
② 轻滑一次 | 标题=2026 年 11 月 | 视口首行=2026-11-02 | 可见 2026-11-02 … 2026-12-20
   轻滑结果：走了 1 行（0=没动 1=一行 6=整月）
```

证据：`verify/ui-cal-scroll-before.png`（起始）、`verify/ui-cal-scroll-1.png`（轻滑后）。

### 2. 大力滑 = 惯性连续滚多行

```
   大力滑结果：滚出可见范围（连续滚多行）
```

证据：`verify/ui-cal-scroll-fling.png`。

### 3. 跨月无缝（10/26~11/01 这一行）
