# 首页两处改动 — 2026-10-26（真机 5bf0cda4 实测）

> 只改 `android/`。两处都在首页：倒数日卡改参考图的 1:1 方形版式；月历日期数字调小。

## 1 · 倒数日卡：改成参考图的 1:1 方形卡

### 改了什么

| 项 | 改前 | 改后 |
|---|---|---|
| 版式 | `fillMaxWidth` 整宽深色卡 | `aspectRatio(1f)` 方形卡，**两列网格**（`chunked(2)` + `weight(1f)`，末行单卡补 `Spacer` 保持方形） |
| 标题 | `maxLines=1` + `TextOverflow.Clip`（长标题被硬裁） | `maxLines=2` + `Ellipsis`，**居中**，13sp 浅灰 |
| 数字 | 48sp 固定，左右夹「已经/还有」与「天」 | **只有数字**，白色 Bold，字号按剩余盒子实测宽高自适应（24~62sp） |
| 方向词 | 数字左侧 + 右侧「天」 | 单独一行浅灰小字，挂在标题下方：`已经 372 天` / `还有 N 天` / `就是今天` |
| 目标日 | `rangeFull().replace("-",".")` → `2025.10.19`（月日未去零） | 新函数 `MemoFormats.compactDate()` → `2026.2.6`（点分隔、月日不补零） |
| 装饰 | 无 | **无**（参考图那颗淡色爱心判定为壁纸/主题效果，按要求不加图形） |
| 语义 | 已完整 | 保持 `倒数日 <标题>，目标日 <YYYY-MM-DD>，已经/还有 N 天` |

### 布局坑（真机实测踩到并修掉）

第一版按「卡宽 / 位数 × 系数」算字号，卡已改成 1:1 但字号还按整宽折算，
2 行标题 + 巨数字 + 目标日总高**超过卡高**，底部 `2026.2.6` 被挤出卡外（dump 里根本没有这个节点）。
改成：数字放进 `BoxWithConstraints(Modifier.weight(1f))` —— 标题/方向/目标日先占位，
**剩余高度全给数字盒子**，再在盒子里取 `min(按宽, 按高)` 折算字号，24~62sp 夹取。
修后 dump 四个文本节点齐全，卡容器 496×496 严格 1:1。

### 坐标证据（真机 1080×2400，density 2.75）

```
卡片容器  bounds=[33,1653][529,2149]   496 × 496  ← 1:1
标题      text="TogetherDays"          [66,1686][496,1826]   （2 行换行放下 12 字标题）
方向      text="已经 262 天"            [155,1837][408,1898]
数字      text="262"                   [160,1898][403,2055]  ← 白字 Bold，157px 高 ≈ 57sp
目标日    text="2026.2.6"              [158,2055][405,2116]  ← 点分隔、月日不补零
语义      content-desc="倒数日 TogetherDays，目标日 2026-02-06，已经 262 天"
```

### 方向词最终位置

**标题下面单独一行小字**（不是塞进标题、也不在数字两侧）。理由：
参考图把「在一起已过」写进标题，但那是**用户自己写的 memo.title**，往里追加「已经/还有」
就是篡改用户数据（标题会跟着进同步、进桌面组件）。所以保留 title 原样居中，
方向词降级为紧随其后的浅灰小字，视觉层次仍是「小字在上、巨数字在下」，与参考图一致；
数字行保持纯净（只有数字）。今天为目标的补了独立文案「就是今天」（不写「还有 0 天」）。

## 2 · 首页月历：日期字号 17 → 15sp

| 项 | 改前 | 改后 |
|---|---|---|
| 日期数字 | `17.sp` | `TookDims.calendarDateFont = 15.sp` |
| 今天圆底 | `.size(34.dp)` | `TookDims.calendarTodayCircle = 30.dp` |
| 格子宽度 | 7 列均分 × 1.5（横向滚动） | **不动**（用户上一轮明确要求） |
| 格子高度 | 98dp | 不动（字号降后留白自然变大） |

两个数值都收进 `Theme.kt` 的 `TookDims`，页面里不再写裸数字。
